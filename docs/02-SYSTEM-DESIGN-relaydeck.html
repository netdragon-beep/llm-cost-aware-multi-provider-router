1. 核心设计：Agent 自动接入与模型配置

本节实现 PRD 的 R-10，并复用 R-04 已发布模型目录、R-06 配置预览/备份和 R-07 模型映射能力。目标是把“网关可用”闭环到“用户的 Agent 已可直接选择并调用模型”。

读取已发布公共模型→选择目标 Agent→适配器编译候选配置→预览、备份、原子应用与验证

1.1 Agent 适配器注册表

字段职责约束
应用标识与检测规则识别 CLI、桌面快捷方式或配置文件是否存在。检测成功仅说明本机可能安装，不能推断可安全改写。
集成等级full、detect_only、candidate。只有 full 显示“配置到 RelayDeck”入口。
配置编译器将网关地址、安全密钥引用、已发布模型目录和可选快捷映射编译为应用格式。必须保留不属于 RelayDeck 的原有配置。
验证器与恢复器解析候选配置、写后重读验证、列出并恢复备份。写入异常时恢复本次备份；备份路径必须限制在该应用受控目录。

1.2 当前适配范围

等级应用编译策略
fullCodex写入 RelayDeck Provider、模型目录与可管理槽位；保留其他 Provider。
fullOpenCode合并 RelayDeck Provider，并写入所有已发布公共模型及其 modalities；保留其他 Provider。
fullClaude Code写入 Anthropic 兼容入口与可编辑 Claude 型别名；保持现有非 RelayDeck 设置。
detect_onlyWorkBuddy、百度搭子 DuMate只检测与说明。DuMate 当前明确不支持外部网关；WorkBuddy 的安全网关配置方式仍待官方格式验证。
candidate其他登记 Agent先验证官方配置格式、外部网关/自定义模型能力、模型发现方式、备份恢复与端到端调用，再升级。

1.3 自动配置事务

  1. 从 RelayDeck 状态读取已发布公共模型，而不是读取所有草稿。
  2. 适配器读取目标配置和环境引用，生成候选文本、差异和影响摘要；不回传敏感值。
  3. 用户确认后创建一次可识别备份，原子写入候选配置，再重新解析。
  4. 解析成功后记录本地活动和模型数量；解析失败时立即恢复备份，并给出配置语法、权限或路径错误类别。
  5. 返回是否需要重启 Agent，以及模型目录/快捷映射将如何在该应用中呈现。
禁止绕过：不得因 Agent 已安装、CLI 位于 PATH 或用户曾打开过该应用，就直接写入其配置。没有适配器的应用只能检测和说明。

2. 架构与所有权边界

Agent / 客户端→协议入口
4100 / 4101→LiteLLM 与路由配置→供应商 API 分组

管理台前端

负责可视化、表单校验、浏览器本地偏好、短期视图缓存和管理 API 调用。不得直接读写系统文件、执行 shell 或保存明文密钥。

管理台后端

负责受管状态校验、同步任务、配置编译、备份、服务操作协调、错误归类与审计摘要。

网关执行层

LiteLLM 和 Claude 兼容入口负责协议转换、上游调用、重试与回退；不承载 UI 草稿和 Agent 备份职责。

Electron 桌面壳

负责窗口、托盘、受限 IPC、启动或复用本地服务。只停止自身拥有的进程，内嵌页面无 Node 权限。

单一真相：供应商、API 分组、公共模型和绑定属于 RelayDeck 受管状态；运行配置只由发布动作编译生成，不能成为独立手工真相。

3. 实体、状态机与关系

实体关键字段/状态所有者与约束
Provider名称、启用状态、API 分组集合。管理台受管状态；删除前需处理关联分组与绑定。
API Profilebase URL、上游协议、密钥引用、启用状态、同步模型、测试摘要。属于一个供应商；密钥值仅存在受保护位置或环境引用中。
Model Family分类名称、排序、未分类标志。展示层组织；不决定上游协议。
Public Model稳定名称、系列、置顶、发布状态、绑定集合。所有公共模型应在管理视图出现；只有已发布模型进入客户端目录。
Upstream Binding原始模型、API 分组、优先级、启用状态、最近测试。属于公共模型；发布编译器只读取有效绑定。
Agent Backup目标应用、配置路径标识、创建时间、摘要、恢复状态。仅本地保存；一次应用动作只产生一个业务备份。

3.1 公共模型状态

草稿 → 已保存 → 置顶待发布 → 已发布
             ↘ 已禁用 / 未发布
同步发现的原始模型 → 已分类待映射 | 已绑定 | 未分类待人工处理

禁止把“发现到原始模型”或“草稿已保存”显示为“已发布”。发布失败后必须保留原草稿和最近一次已成功运行配置。

4. 关键执行流程

4.1 API 模型同步

  1. 前端发起同步并获得任务标识；同一 API 分组同时只允许一个同步任务。
  2. 后端根据上游协议调用模型发现接口，归类网络、认证、超时、格式不兼容等错误。
  3. 同步结果写入 API 分组的原始模型快照，执行确定性规则与可解释匹配候选。
  4. 无法高置信绑定的模型写入未分类/待映射集合；不创建虚假公共模型绑定。
  5. 前端仅定向刷新该 API 分组、相关系列与计数，并给出可读的完成摘要。

4.2 发布路由

  1. 后端从受管状态读取已置顶、启用且拥有有效绑定的公共模型。
  2. 编译生成 LiteLLM 与 Claude 网关所需配置，保留现有运行配置作为失败回滚候选。
  3. 原子写入本地生成配置，并受控重启或热加载受影响服务。
  4. 调用健康/模型发现端点确认生效；失败时恢复上一次成功配置并返回明确阶段错误。

4.3 Agent 配置应用

  1. 适配器检测安装、读取当前配置和密钥来源，不返回密钥值。
  2. 后端生成差异预览、影响摘要和备份计划；前端必须先展示预览。
  3. 用户确认后，创建一次备份，合并允许修改的字段并原子写入目标配置。
  4. 重新读取并解析写入后文件；失败则恢复本次备份并报告原因。
  5. 返回是否需重启、模型目录更新结果和恢复入口。

5. 管理接口与交互契约

接口命名可依现有代码调整，但响应语义必须保持。所有响应禁止携带明文密钥、Cookie、完整环境变量或私密日志。

契约输入输出/错误语义
同步模型API 分组 ID。任务状态、发现数、分类数、待映射数、错误类别与可读摘要。
保存路由草稿公共模型、绑定、优先级、启用/置顶意图。受管状态版本；不声称网关已生效。
发布路由发布目标或全量受管状态。生成版本、服务重载状态、模型发现校验；失败时返回编译/写入/启动/就绪分类。
预览 Agent 配置Agent ID、用户选择的 RelayDeck 设置。当前摘要、计划差异、保留项、备份数量、密钥引用来源、重启要求。
应用/恢复配置经预览确认的操作或备份 ID。操作 ID、一次备份记录、写入验证、恢复结果和可行动错误。
服务状态无敏感输入。管理台、LiteLLM、Claude 网关各自的就绪状态、最后检查时间和诊断摘要。

5.1 前端异步状态

  • 未开始：操作入口说明影响范围。
  • 进行中：按钮用动作文本替代原标签，避免重复提交，并保留可追踪反馈。
  • 成功：提示数量、结果和下一步；仅失效受影响缓存。
  • 失败：显示认证、网络、超时、格式、服务未就绪或未知等分类，不抹掉已有成功数据。

6. 持久化、配置与启动

数据类别位置/形式规则
受管路由状态RelayDeck 本地状态文件或数据库。管理台读写；修改后有版本/更新时间；不提交仓库。
运行配置生成的 LiteLLM/Claude 网关配置。只由发布编译器写入；保留上次成功版本以便回滚。
Agent 原配置与备份目标 Agent 用户目录的受控备份位置。按 Agent 与时间隔离；恢复只作用于对应目标。
主题与视图偏好浏览器本地存储。不影响网关，不纳入服务器状态。
日志与运行 PID本地日志/运行目录。Electron 只记录并管理自己创建的进程。

Windows 与 macOS 的启动脚本可不同，但上层服务语义、状态端点和本地数据边界必须一致。macOS 凭据使用 Keychain，Windows 使用当前用户受保护机制；状态文件只保存引用或加密材料，不保存可读密钥。

7. 安全与隐私控制

  • 前端、桌面 IPC、诊断 API 和测试输出均不返回 API Key、授权 Cookie、密码或完整环境变量。
  • Electron 使用 contextIsolation: true 和 nodeIntegration: false；IPC 只接受固定动作，不执行任意命令。
  • 配置预览展示键名、来源和是否改变，绝不展示密钥值。
  • 浏览器登录只能在用户可见的隔离浏览器会话中完成；验证码、二次验证和账户选择由用户处理。
  • 仓库必须忽略本地状态、日志、运行 PID、生成配置、备份和会话数据；发布前进行密钥检查。

8. 失败处理与可观测性

失败类别检测点用户可见处理
服务未就绪健康端点探测。分别显示管理台、LiteLLM 或 Claude 网关不可用，并给出日志/重启入口。
上游认证或网络失败网络测试或模型发现。保留上次模型快照，显示 API 分组和可行动错误分类。
上游模型不支持对话测试或调用响应。显示原始模型、公共模型、协议能力与上游失败摘要。
发布失败编译、写入、重载、健康校验任一阶段。回滚到最近成功配置，保持草稿，显示失败阶段。
Agent 配置写入失败合并、原子写入或重新解析。恢复本次备份，保留预览，提示目标文件和非敏感原因。

优先级、健康、额度、成本和延迟在当前版本中用于展示、诊断和人工决策。除非发布配置明确启用策略，不能把它们描述为自动熔断或严格主备。

9. 测试、发布与运行验证

风险最小验证额外证据
前端视图/交互定向单元或 DOM 测试。浏览器或桌面端实际检查；确认窄屏、重复点击和反馈状态。
状态与配置生成后端单元/契约测试。临时状态下验证草稿、发布、回滚和敏感字段脱敏。
网关/协议集成配置加载和健康端点测试。安全、非计费或最小化端到端请求；区分配置缺失、上游失败和响应错误。
Agent 配置同步适配器合并和备份恢复测试。临时用户目录或受控样本上的预览、应用、恢复循环。
桌面生命周期主进程/服务管理器契约测试。启动、复用、隐藏到托盘、显式退出及仅停止自有进程的手动验收。

发布前必须检查工作树差异与敏感文件；提交或推送需另行获得用户授权。本文档本身不授权部署、发布或修改用户凭据。

10. 发布与回滚标准

  1. 发布候选必须通过与变更风险相符的自动检查，并记录可复现命令。
  2. 涉及网关或配置写入的变更必须确认运行服务的健康状态，不能只凭构建成功判定完成。
  3. 路由发布失败时恢复最近成功运行配置；Agent 写入失败时恢复本次备份；两者均不删除用户原始数据。
  4. 若发现密钥泄露、跨客户端配置损坏、服务不可启动或模型目录错误，停止进一步发布，保留证据并以最小可恢复步骤处理。
