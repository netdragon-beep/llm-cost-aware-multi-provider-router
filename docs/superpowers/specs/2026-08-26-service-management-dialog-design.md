# 服务管理弹窗设计

## 目标

让 RelayDeck 的服务状态和服务操作保持统一：顶部状态栏负责全局概览，左侧导航负责进入服务管理，服务启停操作集中在弹窗内完成。

## 交互范围

- 左侧保留管理台、LiteLLM 网关和 Claude 网关三个服务入口。
- 左侧移除 `LISTENING`、`DOWN` 等旧状态胶囊，也不直接显示启停按钮。
- 点击服务入口打开可复用的“服务管理”弹窗。
- 弹窗显示服务名称、运行状态、端口、简短职责说明及可用操作。
- 服务运行时提供“停止服务”“重启服务”；服务未运行时提供“启动服务”。
- 操作执行期间在弹窗内显示进行中状态，完成后刷新状态；失败时保留弹窗并显示错误原因。
- 顶部状态栏继续显示所有服务的全局红绿状态，不改变现有状态接口。
- LiteLLM 的“客户端集成”保留在左侧外层，不移入服务弹窗。

## 实现边界

- 复用现有 `/api/service-status` 与 `/api/service/{service}/{action}` 接口。
- 复用现有服务状态轮询和浮动提示机制，不新增服务控制后端。
- 只调整管理台左侧服务区的 DOM、弹窗状态和事件绑定。
- 管理台服务本身只展示运行状态，不提供停止自身的操作，避免关闭当前控制页面。

## 验收标准

- 三个左侧入口视觉统一，外层不再出现旧状态胶囊。
- 点击入口后能打开对应服务的管理弹窗，关闭后回到原页面。
- 启动、停止、重启操作均有进行中、成功和失败反馈。
- 顶部红绿状态与弹窗中的状态来自同一次服务状态刷新。
- 客户端集成按钮仍可在左侧直接使用。
- 现有服务状态 API、路由页面和 Electron 测试不回归。
