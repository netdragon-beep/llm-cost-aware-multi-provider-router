# 供应商价格版本与额度面板设计

## 目标

RelayDeck 在供应商层展示共享额度进度，在 API/价格分组层保存带生效时间的价格版本。用户为每个供应商选择价格自动化策略；适配器只能声明和返回价格能力，不能自行获得自动改价权限。

## 供应商面板

供应商共享额度面板顶部直接显示该平台最近一次额度快照：历史累计总额、累计已用、当前剩余、使用比例、刷新状态和刷新时间。进度口径固定为“累计已用 / 历史累计总额”。数据缺失时显示明确的未知状态，不以零代替。

独立浏览器 SSO 保持为主要登录入口。`auth_token`、`session_cookie` 等手工输入移动到默认收缩的“高级登录修复”区域；普通用户只看到凭据是否受保护、重新授权和清除会话。

## 自动化策略

每个供应商平台保存一个 `pricing_automation`：

- `manual`：只接受用户创建的价格版本。
- `detect-confirm`：适配器价格变化进入待确认列表，默认值。
- `auto-apply`：相同观察连续出现两次且涨跌幅不超过 50% 时自动生效，否则仍要求确认。

策略在供应商层设置，价格记录按 API Profile、价格分组和上游模型分别保存。

## 价格版本

价格版本保存在本地 SQLite，包含：供应商平台、API Profile、上游模型、分组名称、基础输入/输出价格、倍率、最终输入/输出价格、币种、生效起止时间、来源、可信度、状态和指纹。

状态包括 `candidate`、`active`、`rejected` 和 `superseded`。同一 API Profile 与上游模型只能有一个当前生效版本。新版本生效时关闭旧版本，但不修改历史用量记录。

指纹只使用会影响价格的标准化字段，不使用分组显示名称，因此只改名称不会创建价格变化。

## 适配器契约

适配器清单可以声明 `fetch_pricing`。脚本结果可附带 `pricing_catalog`：

```json
{
  "pricing_catalog": [
    {
      "upstream_model": "gpt-5.4",
      "group_name": "Pro",
      "base_input_per_1m": 10,
      "base_output_per_1m": 40,
      "multiplier": 0.5,
      "currency": "USD",
      "effective_from": "2026-07-20T00:00:00+08:00"
    }
  ]
}
```

核心负责标准化、计算最终价格、比较指纹、创建候选或自动生效。字段不完整时保留旧价格，不使用空值覆盖。

## 第一阶段范围

第一阶段交付额度进度条、收缩的高级凭据区、自动化策略、价格版本 SQLite、手工版本 API、候选确认/忽略 API、适配器价格目录接入和管理页价格历史摘要。

完整现金成本归因、充值批次加权平均、套餐按日摊销和所有真实网关请求绑定价格版本属于第二阶段。第一阶段不会伪称现有管理页测试请求等同于完整生产流量。

## 验证

测试覆盖数据库版本切换、同名变更忽略、三档策略、连续观察保护、异常涨跌保护、额度进度显示、凭据区默认收缩和适配器清单能力。运行全部 Python/Node 测试、静态语法检查并在浏览器核对管理页。
