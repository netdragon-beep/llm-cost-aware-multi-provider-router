RelayDeck Local

本地自托管模型路由台，围绕 LiteLLM、Claude 网关和管理页，把路由、密钥、日志、测试与启停动作收在同一个地方。
性价比分析 查看余额额度 模型路由配置 系统设置 诊断工具

Model Routing Desk

这里不是通用 Swagger，也不是聊天页。它服务于你的本地模型网关运维：编辑模型别名、管理环境变量、校验上游 relay，并对 LiteLLM 与 Claude 网关执行受控启停。

用量与额度

展示 token、额度进度、充值记录与供应商真实成本对比。当前版本以手工额度配置和本地 usage 统计为主。

额度进度

每个 API 账户一条进度线，后续也可以扩展成共享 billing pool。

充值记录

录入真实人民币充值金额，用于反推每百万 token 的实际成本。

性价比对比

只展示有真实支出依据的已使用模型；未补充实际支出的额度批次不会进入统计。

模型路由

先配置供应商和 API，再按模型挂接多个上游。支持按模型和按供应商两种方式查看与编辑同一套路由状态。

客户端接入配置说明

          
这里说明两个网关的分工，以及一键配置 Claude Code 会修改的内容。

        

        
      

      

        
Codex / OpenAI 客户端：使用 4100 端口和原生公共模型名称。适用于 Codex、OpenCode 以及其他 OpenAI 兼容客户端。

        
Claude Code：使用 4101 端口和专用模型别名。点击“配置 Claude Code 自动发现”后，RelayDeck 会写入 Claude Code 的用户配置，并启用模型发现。

        
两套网关的关系：端口和模型名称不同，但底层共享同一批供应商、优先级、额度状态和自动故障转移规则。

        
配置完成后：完全退出并重新启动 Claude Code，再使用 /model 选择当前已发布的模型。

        
API Key：客户端只填写 API Key 本身；授权头由客户端自动按 Authorization: Bearer <API Key> 发送。
